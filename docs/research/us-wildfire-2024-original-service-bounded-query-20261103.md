# US wildfire 2024 original service: bounded read-only field/value receipt (2026-11-03)

**Observed original-service read-only responses; research-only.** No source dataset was downloaded, no complete provider asset SHA-256 was pinned, no private database was written, and no original event identifiers, coordinates or records are reproduced here. Queries used the publisher's publicly documented ArcGIS REST services via a web extraction client; response bytes were not retained or hashed as an original asset receipt. Response record counts are deliberately small **sample counts, not population statistics**.

## Correction to the original schema import assumptions

- **Confirmed defect and publisher semantics:** `PERIM_ID` is advertised as a String field in the original MTBS 2024 polygon schema but is **not reliably populated**, because it is the **optional imagery scene ID used to help delineate a perimeter when the pre/post imagery are inadequate**. It is **not a perimeter/geometry row primary key** and must never become the mandatory `mtbs_component_id`. This is documented in the [USFS/USGS MTBS boundary attribute dictionary as published in Google Earth Engine](https://developers.google.com/earth-engine/datasets/catalog/USFS_GTAC_MTBS_burned_area_boundaries_v1). The safe metadata map sets the conversion to `null`.
- `MAP_ID` is documented as **an identifier for a specific mapping activity**, not a physical wildfire event ID or polygon component key. It was nonempty and distinct in the 25-row sample but is **not proven globally unique, stable across MTBS releases or suitable to distinguish multi-polygon components**; do not promote it automatically.
- **Verified narrow original-ID bridge:** The FPA `MTBS_ID` and MTBS `FIRE_ID` match for one selected 2024 record, not proof of a one-to-one population join. Keep FPA `FOD_ID` separately as the record primary identifier.
- `FIRE_TYPE` has observed textual values `Wildfire` and `Prescribed Fire`. The publisher MTBS attribute dictionary also lists `Wildland Fire Use` and `Unknown`. The metadata preflight implements the explicit, conservative `classify_mtbs_fire_type` helper: `Wildfire` maps to `wildfire`, `Prescribed Fire` to `prescribed`, and both `Wildland Fire Use` and `Unknown` to `unknown`. Missing, changed or novel values are `unknown` with an unrecognized flag and **must never default to wildfire**. This mapping does not confer original-data admission.
- These live ArcGIS endpoints can change. Without original archive bytes, published source release, original metadata/record snapshot hashes and a licensed bounded sample pipeline, this receipt proves only that the APIs responded at the time of access and the sample fields existed.
