# Source usability cohort: source semantics, actual access, and Neon quality gates (2026-11-03)

**Classification: research-only evidence. No new source admission, acquisition permission, model approval, production DB write, or external data stored in Git.** This is a bounded cohort, **not an audit of all 281 discovery candidates**. The source of truth for published source rights remains each accepted `manifests/*.json` plus `docs/source-reviews/`, and for technical probes the exact `access/*.json` contract.

## What was actually executed

- A single aggregate-only `SELECT` against the existing Neon `insurance-risk-core`, default branch `main`, database `insurance`, using [the exact review SQL](../../research_runners/sql/source_usability_cohort_audit_v0.sql). No rows were inserted, changed, admitted or exported.
- Read official public **metadata/index representations** for geoBoundaries DEU ADM1, LUX ADM1, FRA ADM2; DWD historical 10-minute extreme-wind directory and station metadata directory; NOAA Storm Events published file directory; and PEGELONLINE's station catalogue. These were accessed through a web retrieval intermediary, **not** via the project's trusted no-redirect, byte-hashed provider probe runner. They prove readable provider representations through that interface on the observed date, not original-response SHA-256 or stable availability.
- Attempted the reviewed exact Dresden station-metadata URL and the one-event EMSC route with the retrieval intermediary: both gave **no parseable payload** in this environment. This is **unverified here**, not provider failure. A fixed NOAA CO-OPS one-day water-level query similarly did not produce a parseable payload; its documented rights and API existence are not a successful query result.
- Reviewed existing first-party original-asset receipts and source-specific tests in this repository; did not repeat the original provider-byte acquisitions.

**Interpretation limits:** A well-shaped 64-hex-character response hash is not independent authentication of the publisher's actual bytes. The SQL validates value domains and the presence/shape of stated keys/receipts; it does not prove spatial completeness, timeseries homogeneity, contractual authority, scientific frequency calibration or insurer allocation. In the directory, repeated country+normalized-name keys may represent classes or distinct legal entities; **do not delete them**. The Ponthierry building SHA check checks RNB and IGN response-receipt format, but historical 2016 property existence, 2016 inundation depth, insured replacement value and vulnerability remain *unproven*.

## Prioritised causal next steps

1. **Build the first scientifically defensible regional chain.** For the 2016 Seine case: distinguish historical discharge, modelled flood depth, observed footprint and regulatory zone; independently resolve invalid original flood topology and exact AOI/vintage/source rights before any building overlay.
2. **Freeze the remaining observational origins.** USGS original-response and USGS ShakeMap product/version rights must be reviewed separately; Hubeau/PEGELONLINE time-series must carry units, station, timestamp and quality status.
3. **Lock a geographic and building provenance bridge.** Keep geoBoundaries original licence and year **per region**; join to official national IDs and verified building vintage. The Luxembourg 2017 ODbL ADM1 snapshot is an example of why a generic global rights statement is insufficient.
4. **Prove the wind/tropical-cyclone route.** DWD homogeneous stations and NOAA observed IBTrACS need explicit intensity/magnitude conventions, STORM v4 needs original track acquisition and calibrated spatial hazard. No direct ELT/YLT from a track CSV.
5. **Insurance context last.** Resolve 18,180 name candidates against official regulators/LEIs, then use defensible financial reporting data; only then estimate explicitly labelled synthetic portfolios. Insurance positions and loss contracts cannot be read out of a names list.

## Follow-up: 2016 Seine Hub'Eau historical daily-flow QA (live read-only SQL)

A second **executed** aggregate query, [Hubeau 47-day station QA](../../research_runners/sql/hubeau_2016_47day_source_quality_audit_v0.sql), checks every date in the stored research slice, exact units conversion, source hash *format*, status/qualification/method code groups, and explicit rights/physical-event/model flags. It was run on CAT-only Neon `insurance-risk-core/insurance/main` without writes. The observed source is the historic mean-daily discharge QmJ (litres/s as published; m³/s derived by /1000), **not** instant peak discharge or flood depth.

| --- | --- | --- | --- | --- | --- | --- | --- |
| F447000302 | 47 / 47 (15 May–30 June 2016) | 47 / 0 | 7 / 40 | 0 / 7 / 40 | 268.866–1,299.307 | 47/47 well-formed, **one shared response hash** | 0 / 0 / 0 |
| F700000103 | 47 / 47 (15 May–30 June 2016) | 0 / 47 | 0 / 47 | 10 / 2 / 35 | 373.005–1,745.481 | 47/47 well-formed, **one shared response hash** | 0 / 0 / 0 |

**Critical scientific observation:** the 94 stored records are complete *within this selected 47-day window*, but they are **not 94 independently obtained source responses**. Each station's rows share one response SHA; independent acquisition authenticity is not established merely by hash-format checks. Code 12 vs 16 in the **status** column distinguishes prevalidated vs validated under SANDRE observation-status nomenclature 514; qualification code 12 and method code 4/8/10 are retained separately and require exact versioned nomenclature review before quantitative filtering. These are **different columns and codes**. In particular, it is misleading to call all 94 values uniformly validated. This cohort did not independently fetch the source payload or verify its original SHA at the provider.

Official references: [Hub'Eau Hydrométrie API v2](https://www.data.gouv.fr/dataservices/hubeau-hydrometrie) documents historic `obs_elab` daily mean QmJ and discharge units (litres/s); [the Sandre hydrometry dictionary](https://www.sandre.eaufrance.fr/definition/OHY/2) distinguishes measurement status, qualification and method; [Eaufrance's API v2 notice](https://www.eaufrance.fr/actualites/evolution-de-lapi-hubeau-hydrometrie) explains status/continuity changes with the v2 migration.

**Next independent checks:** resolve the applicable original provider-response identity, license/service reuse for these exact historic observations, station location/rating-curve/quality/continuity flags, and an independently observed 2016 flood footprint or depth grid. A daily mean discharge cannot, without a calibrated hydraulic mapping, directly determine an asset's flood-depth loss.

## Follow-up: all 94 historic QmJ rows checked against live official API (2026-11-03)

This is **new live source-comparison evidence**, separate from the preceding database-internal QA. Two **bounded, anonymous, read-only** official Hub'Eau Hydrométrie v2 `obs_elab` requests were submitted through the connected web-content intermediary with independently constructed fixed parameters:

- `code_entite=F447000302&date_debut_obs_elab=2016-05-15&date_fin_obs_elab=2016-06-30&grandeur_hydro_elab=QmnJ&size=100`
- `code_entite=F700000103&date_debut_obs_elab=2016-05-15&date_fin_obs_elab=2016-06-30&grandeur_hydro_elab=QmnJ&size=100`

Both returned official API field `api_version=2.0.1`, each with `count=47`, 47 distinct calendar-day observations and no continuation page. The responses were **transiently** parsed, not committed to Git, Neon or a persistent original-data store. One read-only Neon `SELECT` independently selected precisely those two station/date windows from `research.hubeau_seine_47day_daily_q_research_v0`.

**Result: all 94/94 station/day identities matched, and 470/470 field comparisons matched without discrepancy** on: exact published discharge in litres/second, observation status code, qualification code, method code and source production timestamp. Dates themselves were used as independent composite join keys, not counted among the five compared fields. Stored bounds match live provider: F447000302 **268.866–1,299.307 m³/s**, F700000103 **373.005–1,745.481 m³/s**. Source production timestamps were consistent with `2026-08-18` for both station series, with distinct source times.

A *live web-content intermediary* is not a controlled byte-exact source acquisition. Thus this establishes an **observed current provider-vs-database semantic match for the frozen 94-row window**, not original HTTP body authenticity, an independently measured original SHA-256, guaranteed future unchanged provider revisions or licensed rights. No CAT model/use/admission flags were changed.

Official source documentation: [Hub'Eau v2 Hydrométrie](https://www.data.gouv.fr/dataservices/hubeau-hydrometrie). The precise original response SHA-256 must still be acquired and attested through an approved original-byte receipt workflow if needed for reproducible scientific runs. **All 94 remain research-only:** the current `original_licence_reuse_reviewed`, `physical_flood_event_identity_verified` and `model_input_admitted` flags are false. No loss depth, 2016 asset vintage or insurance TIV is established here.
